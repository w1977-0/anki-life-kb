# 一、规范 —— 这套系统是什么、为什么长这样

> 版本：v7（形式三分）　|　上一版：A（v6.1 四套版式）　|　更新：2026-09-19
> 改设计看这份。动手部署看 `02-操作.md`。踩过的坑看 `03-踩坑.md`。

---

## 1. 它解决什么问题

用户在飞书里发一段内容 → Hermes 加工 → 写入服务器上的 Anki collection → 同步到手机/电脑。

**价值全在「加工」这一段**，不在搬运。所以规范要解决三件事：

1. 一段内容该做成**什么形式**（通读 / 回忆 / 挖空 / 选择）
2. 做成之后长**什么样**（4 套版式里的哪一套）
3. 改版式 / 改形式时**不会把现有卡片弄坏**

---

## 2. 三个笔记类型

| 笔记类型 | 用途 | 字段 | 卡数 |
|---|---|---|---:|
| **生活摘录** | 主力。摘录型内容（书摘、想法、长文）+ 可自测的概念 | 正文 / 出处 / 我的话 / 类型 / 风格 / 日期 / **自测** | 370 |
| **生活挖空** | 要精确记忆的（文言、定义） | 正文 / 出处 / 我的话 / 类型 / 风格 / 日期 | 4（2 条笔记） |
| **生活选择** | 有明确选项的（概念辨析、常识） | 正文 / **选项** / 出处 / 我的话 / 类型 / 风格 / 日期 | 4 |

「生活摘录」多一个 `自测` 字段，用来在**同一个笔记类型里**分流两种形式（见 §4）。

### ⚠️ `类型` 字段有两个用法，别搞混

| 笔记类型 | `类型` 是什么 | 取值 |
|---|---|---|
| **生活摘录** | **内容性质** —— 决定形式和版式 | 必须是 9 个值之一（见 §7） |
| **生活选择** | **书眉标签** —— 只是显示在卡片顶部 | 可以是领域标签（行测的「常识判断」「资料分析」），**别空着** |
| **生活挖空** | 书眉标签 | 同上 |

原因：`生活选择` / `生活挖空` 的模板**不按 `类型` 分流**，
它只是个标签位；只有 `生活摘录` 用它决定"通读还是回忆、用哪套版式"。

## 3. 形式三分 —— 不是「正反面 vs 单面」二分

判断依据只有一个：**这段内容有没有得答。**

| 形式 | 正面 | 背面 | 适合 |
|---|---|---|---|
| **通读** | 内容**全部展开**（大引号 + 正文 + 出处） | 同正面 + 「我的话」+ 波浪分隔 | 金句、长文、描写、记录、自己的想法 |
| **回忆** | 只给**标题 + 提示** | 出全文 + 我的话 | 定义、论证、文言 |
| **挖空** | 正文挖掉关键处 | 出答案 | 要精确记忆的短句 |
| **选择** | 题干 + 选项（可交互） | 判定结果 | 有明确选项的 |

### 为什么「通读」是对的

用户原话：正面「当时记下了什么」、反面是全文 —— **这完全没必要**。

30 字的金句，看一眼书名想不出那句话，翻面过了，**没有任何认知收益**。
先藏后显只对「能答的东西」有意义；对不能答的东西，它是**假测试**，只是多了一次点击。

### 通读 vs 回忆 的真正差别

不是版式，是**「有没有东西要藏」**：

- **回忆卡** —— 装饰件全关（大引号、波浪、胶带），正面要干净，别抢提示
- **通读卡** —— 装饰件**全开**，因为没有需要藏的，版式本身要撑得住

### 实测数据（决定这套规则的依据）

370 张「生活摘录」真实构成：

| 类型 | 张数 | 正文均长 | 中位 | 最长 | 结论 |
|---|---:|---:|---:|---:|---|
| 句子 | 184 | 41 字 | 30 | 441 | 金句 → 通读 |
| 方法 | 98 | **2190 字** | 1142 | 13302 | 整篇 HTML 文章 → 通读 |
| 观点 | 88 | 160 字 | 98 | 2864 | 能复述要点 → 回忆 |

**76% 的内容适合通读，24% 适合回忆。**

## 4. `自测` 字段：一个笔记类型，两种形式

`生活摘录` 只有**一个模板**，用 Anki 的条件语法分流：

```mustache
<div class="pg skin-{{风格}}{{^自测}} mode-read{{/自测}}">
  …
  {{^自测}}<span class="mark">&ldquo;</span>
  <div class="body">{{正文}}</div>{{/自测}}      ← 通读：正面就有正文

  {{#自测}}{{#出处}}<div class="title">{{出处}}</div>{{/出处}}{{/自测}}
  …
</div>
```

- `自测` **留空** → 走通读
- `自测` **填「自测」** → 走回忆

### ⚠️ 为什么不用「两个模板」

Anki 有「模板 front 渲染为空则不生成卡」的机制，理论上可以拆两个模板。
但**换模板 = 卡的 `ord` 变了 = 生成新卡 = 复习历史全丢**。

现在这个写法：模板 ID 和 `ord` 都不动，只改 qfmt/afmt 内容 —— **370 张卡的 revlog（2232 条）一条没丢**。

## 5. 四套版式

复刻 Quizify 2 套 + 按内容类型补位 2 套。**做精不做多。**

| 版式 | 气质 | 适合 | 关键特征 |
|---|---|---|---|
| `kaiwu` 开务 | 现代、清爽 | 知识 / 概念 / 方法 | 青绿 `#147d72`、赭橙 `#d77a42`、圆角 18px、无衬线 |
| `gezhi` 格致 | 复古、书卷 | 典故 / 文言 / 观点 | 蓝灰 `#5e7987`、象牙白 `#fffef9`、赭色点缀、衬线、四边细框 |
| `paper` 纸白 | 克制、横格 | 长文摘录 / 场景 | 纯白 + 30px 横线格（与行高对齐）、衬线、版心放宽 |
| `memo` 便签 | 轻、短、聚焦 | 短句 / 金句 | 米黄 `#fbf3dc`、正文 20px **居中**、顶部半透明胶带 |

### 加一套版式要改什么

只改 `css/base.css` 里的一段变量覆盖，**不动结构**：

```css
.skin-新名字 {
  --paper: …; --desk: …;
  --ink: …; --ink2: …; --ink3: …;
  --line: …; --accent: …; --accent2: …;
  --fs-body: …; --lh-body: …;
  --pad-t/-r/-b/-l: …;
  --align: left | center;
  --radius: …;
  --font: …;
}
```

四套之间的差别是**结构性**的（字号 / 行高 / 留白 / 字族 / 对齐 / 装饰），不是换个背景色。
如果一套新「版式」只是换个颜色，那它不配独立存在。

## 6. CSS 分层

```
base.css         令牌层(:root) + Anki 容器重置 + 骨架 + 4 套版式 + 长文排版 + .mode-read
   ├─ cloze.css  挖空追加层   → 生活摘录 / 生活挖空 用
   └─ choice.css 选择追加层   → 生活选择 用
```

拼装（追加层写在后面，所以它的规则赢）：

```
生活摘录 CSS = base + "\n\n" + cloze + "\n"   → 14,159 字符
生活挖空 CSS = base + "\n\n" + cloze + "\n"   → 14,159 字符
生活选择 CSS = base + "\n\n" + choice + "\n"  → 16,244 字符
```

`base.css` **不定义任何 `.quiz*`** —— 交互区归 `choice.css` 独有，避免重复规则打架。

### 令牌必须挂在 `:root`

CSS 变量**只向下继承**。桌面色 `--desk` 要被 `.card`（Anki 容器）用到，
而 `.card` 是 `.pg` 的**祖先** —— 挂在 `.pg` 上，`.card` 读到的就是 undefined。

旧版（24 套）挂 `.card`，v6.0 误挂 `.pg`（bug，桌布色失效），v6.1 起改挂 `:root`。

### 桌面色怎么铺满

```css
.pg { box-shadow: 0 30px 80px …, 0 4px 16px …, 0 0 0 100vmax var(--desk); }
```

最后一层扩散阴影把桌面色从卡片向外铺满整个视口。
不用 `:has()`（兼容性），也不用 `.card` 背景色（它读不到每套版式各自的 `--desk`）。

## 7. 完整映射：内容 → 形式 → 版式

| 类型 | 形式（`自测`） | 版式池（轮换） | 正文字数上限 |
|---|---|---|---:|
| 句子 | 通读（空） | `memo` → `kaiwu` → `paper` | 60 |
| 典故 | 回忆（自测） | `gezhi` → `paper` | 60 |
| 概念 | 回忆（自测） | `kaiwu` → `memo` → `paper` | 80 |
| 观点 | 回忆（自测） | `gezhi` → `paper` → `kaiwu` | 150 |
| 感悟 | 通读（空） | `memo` → `gezhi` → `paper` | 80 |
| 方法 | 通读（空） | `kaiwu` → `paper` → `memo` | 150 |
| 场景 | 通读（空） | `paper` → `gezhi` → `kaiwu` | 120 |
| 事件 | 通读（空） | `paper` → `kaiwu` | 80 |
| 里程碑 | 通读（空） | `kaiwu` → `memo` | 60 |

同一批卡同一类型**按顺序轮换**版式，不要连续两张用同一套。

## 8. 长文排版（容易漏）

「方法」类 98 张的正文是**带 `<table>/<ul>/<li>/<strong>/<a>` 的整篇 HTML**
（中位 1142 字，最长 13302），不是纯文本。`base.css` 必须给全：

| 元素 | 处理 |
|---|---|
| `p` | 段间距，最后一段不留 |
| `ul/ol/li` | 缩进 1.5em（不吃版心），marker 灰 |
| `strong/b/em` | 提到 `--ink`（正文是 `--ink2`），有对比但不跳 |
| `a` | accent 色 + **`word-break: break-all`**（b 站搜索 URL 不断行会撑破版心） |
| `table` | 细边框 + 表头浅底 + `width:100%` |
| `h1-h4 / hr / blockquote` | 间隔 + 灰线 / 灰竖线 |

⚠️ 数据里还有复制粘贴污染：部分「我的话」字段塞进了完整的
`<meta charset>/<title>/<style>` 网页源码。清理是另一件事，见 `03-踩坑.md`。
