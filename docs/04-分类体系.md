## 0. 设计原则（先说清楚，后面才不会走形）

**① 这套体系不是从现有 410 张卡归纳出来的。**
它是按"一个人一辈子的知识长什么样"先搭好骨架，再把现有卡放进去。
所以里面会有你现在一张卡都没有的分类 —— **那是预留位，不是错误**。
空着没关系，编号在那儿，等你需要时它就在。

**② 牌组回答"我什么时候会用到它"，不是"它讲什么"。**
内容讲什么由**笔记类型的「类型」字段**管（句子/观点/方法…），
牌组管的是**处置方式**：要不要天天练、还是做事时翻、还是归档。

这两个轴是**正交**的，别混：
| | 谁管 | 决定了 |
|---|---|---|
| **牌组** | 你怎么用它 | 什么时候复习、和什么放在一起 |
| **类型字段** | 它是什么 | 用什么形式（通读/回忆）、什么版式 |

**③ 编号永不回收。**
一个分类删了，编号**留空**。新分类用新号，不复用旧号。
这是 Johnny Decimal 最硬的一条，也是"长期"两个字的全部意义：
十年后你改了名字、换了顺序，**编号没变，东西还在原位**。

## 1. 六个顶层

```
00：系统        这套体系本身：说明、收件箱、待改写
10：在练        要靠重复真正长到身上的（有"掌握"标准）
20：在用        已经会了，做事时会翻出来调用
30：读过        别人写的，我留下来当素材
40：记过        我自己经历的、自己想的
90：归档        不进日常循环的
```

**顺序 = 活跃度。** 从上到下，复习频率递减。
这不是主题分类，是**处置层级** —— 借的是 PARA 的"行动性"思路。

判定一句就能说清：**这张卡，我是要"练会它"，还是"用到时查它"，还是"留个纪念"？**

## 3. 为什么是这些分类（借鉴了什么，放弃了什么）

| 体系 | 借鉴 | 放弃 |
|---|---|---|
| **PARA** | 顶层按**行动性**分层（练 / 用 / 读 / 记 / 归档），不按主题 | Projects 层 —— 项目有截止日期，Anki 卡没有 |
| **Johnny Decimal** | **编号永不回收、名字可改**；每区 ≤10 类；用 `.` 扩展层级 | 纯数字（`10.01` 不带名字）—— 加了名字才看得懂 |
| **Zettelkasten** | — | **整套放弃**。它的价值在卡片之间的链接，而 Anki 牌组是树，没有链接机制，硬套长不出网络 |
| **中图法** | 22 大类的"覆盖全"意识 | 太重，个人用不上 |

### 为什么放弃 Zettelkasten 值得单独说

很多人把卡片盒和 Anki 混为一谈。区别在载体：
卡片盒靠**链接**产生新想法，Anki 靠**排程**让你记住。
你要在 Anki 里长出新想法，靠的是你脑子里已有的连接，不是牌组结构。
所以牌组只要做到一件事：**让你在该看到它的时候看到它。**

## 5. 日常怎么用（三条就够）

1. **飞书 / Hermes 进来的，先落 `00.02：收件箱`**，别直接猜分类。
   分流是二次动作，混在一起会毁掉收件箱的意义。
2. **拿不准放 10 还是 20，就问一句**："我要练到不用想就能做出来吗？"
   是 → `10：在练`；不是 → `20：在用`。
3. **书摘一律进 `30.01：书::<书名>`**，不管它是金句还是方法。
   `30` 下面第二层管来源，不管内容性质。
