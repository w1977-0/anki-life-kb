## 一、项目研判

| 项 | 实测 |
|---|---|
| 性质 | **持续更新的书稿**（非文章合集），源起 2017《离谱的英语学习指南》 |
| 规模 | **37 章 / 387 个 H2 小节 / 19.0 万字** |
| 附带 | 23 个模板、5 篇归档旧文、术语表、词表、**35 张图** |
| 结构 | `# 章` + `## 本章速览` + `## N. 小节`（每章 10–13 节） |
| 小节构成 | 标题（一个可执行主张）+ 核心句 + 要点列表/表格 + 说明 |
| 校验 | SUMMARY 77 条目 ↔ 实际文件，**双向 0 缺口** |

### 与前 4 个项目的根本差异

| | 前 4 个 | **up** |
|---|---|---|
| 体裁 | 条目体 | **散文式方法论** |
| 单元长度 | 多 <150 字 | **中位 373 字**（59.4% 在 300–600） |
| 能否直接做卡 | 能 | **不能，须按"全文通读"处理** |

## 二、切分粒度（**用户已拍板：方案 A**）

**一节一卡 · 全文通读 · 整节全放** → **387 张**

选 A 而非"提炼核心句"的理由：符合本体系已确立的原则
**「资料卡 = 单面通读、正文全量；记忆卡才做问答」**。
提炼会违背"正文全量"，且要点列表才是可操作部分。

### 落地要点

| 项 | 处理 |
|---|---|
| 150 字上限 | **绕过**（复用 `anki_add.py --whole` 逻辑：不拦字数） |
| 版式 | **强制 paper**（克制横格、版心放宽，最适合长文） |
| 标签 | 自动加 `完整保留` |
| 类型 | `长文`（走通读） |
| 例外 | 11 个 >1000 字的小节（最长 5839）照放，不特殊处理 |

## 三、牌组（第 3 步）

按体系判定句——*"这张卡，我是要练会它，还是用到时查它，还是留个纪念？"*
本书是**方法论参考** → **用到时查它** → `20：在用`。

```
20：在用::20.13：《人生进阶指南》
├── 20.13.01：开始              9 节
├── 20.13.02：打开输入        144 节   ← 英语学习（最大板块）
├── 20.13.03：把自己放回生活    80 节
├── 20.13.04：借工具放大能力    63 节
├── 20.13.05：实践与恢复        46 节
├── 20.13.06：行动与长期改变    40 节
└── 20.13.07：后记               5 节
                              合计 387
```

编号接续：`20.09` 人生指南 / `20.10` 做饭指南 / `20.13` 延寿指南 / `20.12` 提问的智慧 / **`20.13` 进阶指南**（编号永不回收）。

⚠️ **踩坑记录**：最初规划用 `20.13`，导入时才发现已被《程序员延寿指南》占用 —— **新建牌组前必须先 `decks --all` 核实编号**，不能凭记忆推。

**为什么 part-1（英语，144 节）也进 `20：在用` 而不是 `10：在练`**：
它讲的是**学习方法论**（"先定义任务"、"让间隔服从表现"），不是单词/句型练习材料。
判定句问的是"怎么用它"——是"做事时翻出来查"，不是"每天练会它"。

## 四、标签体系（第 4 步）

| 标签 | 取值 | 来源 |
|---|---|---|
| `人生进阶指南` | 固定 | 来源标识（便于整批筛选/归档） |
| `部-N<部名>` | 开始 / 打开输入 / 把自己放回生活 / 借工具放大能力 / 实践与恢复 / 行动与长期改变 / 后记 | part 结构 |
| `章-<章名>` | 词汇篇 / 选择篇 / 恢复篇… | 章节 |
| `型-方法` / `型-故事` / `型-原则` | 内容类型 | 见下 |
| `完整保留` | 固定 | 通读型标记（与现有体系一致） |
| `CC-BY-NC` | 固定 | **许可标注**（非商业许可，必须可见） |

**类型判定**（决定标签）：
- `型-方法`：标题是做法（"先判断可逆性"）
- `型-原则`：标题是判断准则（"不要用结果审判当时的决定"）
- `型-故事`：part-2 的叙事章（"我的故事"、"一家公司倒闭之后"）

## 五、卡片形态与句式（第 5 步）

**方案 A 是通读型**——正面显示出【处】+【正文】，所以**不需要设计问句**。

| 字段 | 取值 |
|---|---|
| **出处** | **小节标题**（本身就是主张，天然是好提示） |
| **正文** | 整节全文（md → HTML） |
| 我的话 | 空（或放"本章速览"里对应的一句，待定） |
| 类型 | `长文` |
| 风格 | `paper`（强制） |
| 日期 | 脚本自动填制卡当天 |
| 自测 | 空（通读型） |

⚠️ **与回忆型的关键区别**：通读卡正面就显示正文，所以**不存在"答案泄露"问题**。
（前一轮我在 HowToLiveBetter 上误判过这点，这次先确认类型再判。）

## 六、技术要点（必须处理，否则显示错乱）

| 项 | 数量 | 处理 |
|---|---|---|
| **Markdown 表格** | **795 行** | 转 `<table><thead><tbody>`，否则显示成竖线文本 |
| 代码块 | 74 个 | 转 `<pre><code>` |
| 引用 `>` | 18 行 | 转 `<blockquote>` |
| 外链 | 49 个 | 保留为 `<a href>` |
| 图片 | 35 张 | 若小节内有图 → 走媒体流程（见第八节） |
| 加粗 `**x**` | 大量 | 转 `<strong>`（先转义再加标签） |

**复用**：`htc2cards.py` 里的 `md_to_html()` 已支持表格/列表/引用，直接借用。

## 七、质控红线（第 6 步）

| 规则 | 理由 |
|---|---|
| **每张卡必须标 `CC-BY-NC` 标签** | 非商业许可，署名必须可见 |
| 出处写**真实小节标题**，不写占位符 | 与现有体系的出处规则一致 |
| 正文 HTML 转义 `& < >` | 防止内容破坏渲染 |
| 通读卡不拦 150 字 | 方案 A 的明确选择 |
| 不删原文（不加删节、不"优化"措辞） | "正文全量"原则 |
| 入库前先查重 | 与现有 6553 张比对 |
| **入库后必须跑媒体双向核对** | 前一轮刚踩：正文引用了图但没传文件 → 破图 |
