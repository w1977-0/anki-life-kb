# 08 · PDF / 长文批量制卡作业指导书

> 适用：一本 PDF（多篇文章合集）→ 每篇一张卡 + 目录一张。
> 本文是实操手册，按步骤走即可；每一步都标了"为什么要这样"。

---

## 总流程（7 步）

```
① 收文件   → 只处理用户明确指定的那一个
② 备份     → 动数据前必做
③ 解析     → 提取 + 清洗 + 锚点合并拿完整标题
④ 切分     → 目录 1 张 + 每篇 1 张
⑤ 加工     → 出处 / 标黑 / 白名单
⑥ 写卡     → --whole + --body-file
⑦ 验收     → 三处副本一致 + 同步副本刷新
```

## ① 只处理指定的那一个

**铁律：用户给几个就做几个。** 同目录看到别的文件，**先问**，不擅自处理。

（有过教训：用户给 1 个 PDF 说"继续"，我擅自做了另外 4 个，最后全部删除，浪费大量时间。）

## ③ 解析：提取 + 清洗

**一条命令**（`tools/split_vol.py`，已含提取+清洗+切分+加工）：

```bash
python3 tools/split_vol.py <PDF> <输出.json> [扫描目录的页数]
# 例：python3 tools/split_vol.py "…/81-100.pdf" /tmp/v5.json
```

输出是一张卡一条的 JSON（`n` / `title` / `html` / `plain` / `nkey`），直接喂给写卡脚本。

### 卷次 ↔ 篇号（墨苍离《致爱自己的人》系列）

| 卷 | 篇号 | 页数 | 备注 |
|---|---|---|---|
| （一） | 1–20 | | |
| （二） | 21–40 | | |
| （三） | 41–60 | | |
| （四） | **61–80** | 343 | 文件名原本叫 `61-80.pdf` |
| （五） | **81–100** | 297 | ⚠️ 另有一个 `（5）.pdf` 只是 **81–88 的残本**（161 页），别拿它当卷五 |
| （六） | **101–120** | 278 | |

**拿到 PDF 先翻封面第 1 页**：印着「（X）· 共 N 篇文章」，用它确认卷次，**不要按文件名猜**。

### 五个必踩的坑（按破坏力排序）

**1）页码污染 —— 最坑，会让标题全错**

PDF 的页码不只是页脚那一行。pypdf 提取时它会**粘进行首或行中**：

```
5764. 过度沉迷「成功学」会带来哪些负面影   ← 页码 57 + 编号 64. 粘连
61偏样本如何训练出错误地图                 ← 行首
不76教你什么时候退出                       ← 行中（前后都是中文）
```

后果：编号标题识别不到（64 篇直接消失）、标题变成「房亲戚——」「十二」。

**解法**：按页处理，剥掉**正好等于本页页号 ±1** 的孤立数字：

```python
nums = [int(x) for x in raw[:3] if re.fullmatch(r'\d{1,4}', x)]
pageno = nums[0] if nums else idx + 1        # 页眉页码通常在最前
# 行首 数字+中文 / 行中 中文+数字+中文，且数字 ∈ {pageno-1, pageno, pageno+1} → 删
```

只剥**等于页号**的数字，`2026高考`、`94项研究`、`25分钟` 这类正文数字不动。

残留无法 100% 清（跨页错位的极少数，如 `点1里`、`法11确`），可接受。

**2）必须跨页合并，不能按页分段**

先把**所有页的行收成一条流**再分段，否则跨页的句子会被切两半
（`…下次被一条新闻点着了火，下` / `分早就是定论…`）。

段落结束判据只用句末标点，**不要用行宽阈值**（会把长句切断）：

```python
if s and s[-1] in '。！？':
    blocks.append(('p', buf)); buf = ''
```

**3）标题折行：残片可能在标题中段，不只是尾巴**

两个 `<h3>` 相邻 → 多半是同一标题被折行。合并规则：

- 前一条是「N. 」开头的文章标题 → **无条件**续接后面的短 h3
  （`85. 你如何看待优绩主义呢？…想跨` + `越阶级的人…？` 必须合，尽管前半含 `？`）
- 但后一条若是 `一、` / `Part N` / `第N章` 小节标记，或又是一条编号标题 → **不并**

**4）目录块要跳过**

改进后的提取会**保留目录**，正文里第一次出现的编号标题其实是目录条目。
识别方法：目录是「编号连续 +1、间距 < 500 字符」的一段，其后才是正文。

```python
k = 0
while (k+1 < len(heads) and int(heads[k+1][1]) == int(heads[k][1]) + 1
       and heads[k+1][0] - heads[k][0] < 500):
    k += 1
pos = heads[k][0]        # 从目录块之后开始匹配正文
```

**5）没印目录的 PDF → 从正文锚点补一份**

用户要求「没有目录就补充目录」。用正文里的编号 h3 取**严格递增**的那条链
（自动跳过 `1.` `2.` 这类小节编号，因为它们小于起始篇号）。

⚠️ 目录条目可能**编号后没空格**（`75.为什么很多人…`），正则要写 `[.、]\s*` 而不是 `\s+`，
否则这一篇会整个消失。

**先验证：目录 20 条标题是否完整。** 缺一条就停下修，别往下走。

## ④ 切分 + 去标题回声

- 目录 → 1 张卡
- 每篇 → 1 张卡

切分时**去掉正文里的 h3 标题**（标题已由"出处"承载，正文再写一遍是冗余）。

去掉编号 h3 后，正文开头常残留**标题被折行切下来的碎片**，要清掉：

```python
idx = nt.find(frag[:5])              # frag 是标题的连续子串（可能在中段）
if idx < 0: break                    # 与标题无关 → 是正文，收手
while nt[idx+L] == frag[L]: L += 1   # 能连着对上多少字
if L >= 5 and (len(frag)-L <= 20 or L >= len(frag)*0.6):
    seg = seg[m.end():]              # 整块基本就是标题（剩下的只是副标题）→ 删
```

另有一条「标题截在半句 → 从正文首句补回」的规则，**只在没有印本目录时启用**，
且要求标题以虚词收尾（`里|中|上|下|的|了|是|…`）——否则会把「该交给理解的」
这类正常标题也吞掉正文首句。

## ⑤ 加工（质量核心）

### 出处

| 规则 | 值 |
|---|---|
| ✅ 出处 | `N. 标题` |
| ❌ 不要 | `《书名》· N. 标题` |

**书名由牌组承载**（牌组名用《》），出处不嵌书名 —— 重复且标题过长。

### 牌组

```
30：读过::30.02：文章::30.02.02：<作者>::《书名（卷）》
```

例：`30：读过::30.02：文章::30.02.02：墨苍离::《致爱自己的人（一）》`

### 类型

- 整篇保留的长文 → `长文`
- `长文` = 通读（自测留空）+ 只用 paper + **不限字数、不拆**
- 不要用 `观点`/`概念` —— 它们会自动变"回忆"（先藏后显），对几千字文章是假测试

### 标黑（`<strong>`）

**数量按长度**：

```
<3000 字 → 3 处    3000-6000 → 4 处
6000-10000 → 6 处  >10000 → 8 处
```

**判据（强信号词，必须 。 结尾）**：

```
这就是 | 本质 | 真正的 | 真正 | 意味着 | 决定了
不在于 | 问题不在 | 核心在于 | 核心问题 | 关键在于
不是 X，而是 Y（转折结构）
```

**排除**：

```
？结尾（问句不是结论）
需要说明 | 需要标注 | 诚实地 | 声明 | 局限 | 样本量 | 免责
注意 | 这一条 | 简单说 | 一句话 | 比如
一、二、（章节编号） | 年成立 | 年发表
长度 <12 或 >55 字
```

**白名单转 `*xxx*`**（PDF 里作者用星号表示强调）：

```
只转：拼不过富二代 / 阶层差距存在 / 你个人拼不过某个具体的富二代
      / 谁钱多谁赢 / 拼不过
其余星号直接删掉（h3 里的也删 —— h3 本身已 700 字重）
```

⚠️ **不要无脑 `re.sub(r"\*(.+?)\*", ...)` 全转** —— 会把「家里几套房」这种举例、
「家庭财富」这种学术限定语也标黑。**必须白名单。**

### 验证标黑质量

写完**必须抽查**：

```
每篇 list 一遍 <strong> 内容，看有没有误标。
误标率目标 <10%。误标比漏标更糟（会误导阅读节奏）。
```

## ⑥ 写卡

### 单张（Hermes / 手工）

```bash
python3 .../anki_add.py \
  --deck "<牌组>" \
  --type 长文 \
  --body-file /tmp/xx.html \     # 正文 >100KB 必须用这个
  --source "N. 标题" \
  --whole                        # 整篇保留：强制 paper + 不拆 + 加「完整保留」标签
  --create-deck                  # 新牌组才加
```

### 批量落库（重做某一卷时用它）

`tools/write_volumes.py`（在服务器跑）：

```bash
python3 write_volumes.py <卷四.json> <卷五.json> <卷六.json>
```

**按「编号」匹配已有卡片 → 更新正文；新编号 → 新建；不删任何卡。**

为什么要这样：重做一卷时，大部分篇目已存在。删了重建会丢复习进度（revlog 虽在，
但 card 变了）。按编号更新则进度完好。

实测：卷四 新建 2 / 更新 19；卷五 新建 13 / 更新 8；卷六 新建 21。

⚠️ `c.new_note()` 要传 **notetype id（整数）**，不是名字：
`c.new_note(c.models.by_name("生活摘录")["id"])`。

⚠️ 跑完**必须刷新同步副本**（见 ⑦），否则手机看不到。
**脚本已自带这一步**（`refresh_sync()` 在写完后自动执行并打印核对结果），别再靠记性。

> 教训：这一条我漏过三次。最近一次写完卷七卷八没刷，
> 工作库 3814 / 副本 3773，手机整整少 41 张，而终审**照样报 25/25 全过**。

⚠️ **单参数上限 128KB** —— 长文用 `--body-file`，否则 `OSError: Argument list too long`。

⚠️ **整卷卡会阻塞查重** —— 如果库里已有这本的整卷卡，拆出来的每篇都会被"重复"拦下
（整卷卡包含所有文字，全库短语搜索必然命中）。**必须先删整卷卡再拆。**

## ⑦ 验收（最容易漏）

### 改库要走 CLI，否则推不到同步副本

**直接 `update_note` 改库 = 手机永远看不到**（同步副本没更新）。

- ✅ 用 `anki_cli.py` 的命令（自带同步）
- 或改完手动：`anki_cli.py sync`

如果增量 sync 返回 `NO_CHANGES` 但实际有差异（绕过 CLI 改的），需要**全量替换**：

```bash
1) systemctl stop anki-syncserver
2) checkpoint 工作库：pragma wal_checkpoint(truncate)
3) 只拷主文件 collection.anki2 → sync/anki/
   并删掉 sync 的 -wal / -shm（让它们重建）
4) chown hermes:hermes
5) systemctl start anki-syncserver
```

⚠️ **漏拷 -wal 会导致副本损坏**（`database disk image is malformed`）。
正确做法：**先 checkpoint，再只拷主文件**。

### 验收清单

```
□ 工作库 与 同步副本 卡片数一致      ← 终审【K】项现在会查，但自己也要核
□ 出处无《书名》前缀
□ 标题居中（CSS .pg h1.title text-align: center）
□ 结尾完整（每篇句末标点正常，无截断）
□ 字数守恒
□ 终审 25/25
□ 评估 28/28
```

### 改技能/脚本要改源头

```
anki-deploy/skill/   ← 源头（部署 + Hermes 用的）
        │ build_oss.py
        ▼
oss/skills/          ← 生成产物（会被覆盖，别直接改）
```

改完源头 → `build_oss.py` → 部署服务器 → 重启 gateway → 推 GitHub。
**核对三处一致**（源头 / oss / 服务器各 1 处，别重复插入）。

## 快速排障

| 症状 | 原因 |
|---|---|
| `Argument list too long` | 正文 >128KB，改用 `--body-file` |
| 拆出来的每篇都「被查重拦下」 | 库里还有整卷卡，先删 |
| 改了但手机没变 | 同步副本没刷新，走⑦（脚本已自带，别手动忘） |
| 终审全过但手机内容不对 | 【K】项旧版只查「文件在不在」；新版已改为数量+mod 双比对 |
| 副本 `malformed` | 替换时漏了 -wal，重做⑦ |
| 标题变成「十二」「房亲戚——」「5764. …」 | **页码污染**，见③坑1 |
| 某篇整个消失（如 64、75 篇） | 编号被页码粘住 / 目录条目编号后没空格，见③坑1、坑5 |
| 每篇只有几十字，最后一篇吃掉全部 | **把目录当成了正文起点**，见③坑4 |
| 句子在中间被切断 | 按页分段了，要跨页合并，见③坑2 |
| 标题只留半句 | 折行残片没合并，见③坑3 |
| 正文开头重复标题 | 没做「去标题回声」，见④ |
| 误标一堆 | 全转 `*xxx*` 了，改白名单 |
| `TypeError: 'str' object cannot be interpreted as an integer` | `new_note()` 传了名字，要传 id |
| Hermes 不守新规则 | 改了 oss 没改源头 / 没重启 gateway |

### 每次交付前的自检

```
□ 目录条数 == 篇数（20 篇就要 20 条，缺一条就修）
□ 每篇 plain 字数合理（几百字或几十字都是错）
□ 抽查开头：无标题残片、无页码数字（中文夹 1-3 位数字要人工看上下文）
□ 抽查结尾：句末标点正常
□ 牌组内无重复「出处」
□ 终审 25/25 + 评估 28/28
□ 同步副本 notes 数 == 工作库
```
