## 1. 改 CSS（最常见）

### 步骤

1. 在**本地**改 `design/base.css`（或 `add_cloze.css` / `add_choice.css`）
2. 推到服务器 `/tmp/skins4/`：

```bash
zsh .ssh/push-finance.sh design/base.css      /tmp/skins4/base.css
zsh .ssh/push-finance.sh design/add_cloze.css /tmp/skins4/cloze.css
zsh .ssh/push-finance.sh design/add_choice.css /tmp/skins4/choice.css
```

3. 跑部署脚本（改三个笔记类型的 CSS）：

```bash
zsh .ssh/push-finance.sh anki-deploy/apply_v7.py /tmp/apply_v7.py
./.ssh/ssh-finance.sh "sudo $PY /tmp/apply_v7.py"
```

4. **必须**覆盖同步副本（见 §3）
5. 验证（见 §5）

### 拼装规则（脚本里写死的，别改）

```
生活摘录 / 生活挖空 CSS = base + "\n\n" + cloze  + "\n"
生活选择 CSS           = base + "\n\n" + choice + "\n"
```

## 2. 改模板 / 加字段 / 批量改数据

⚠️ **一律用 `col.update_note(note)`，不要手写 `col.db.execute()` 改数据。**
理由见 `03-踩坑.md` 第 1 条（手写 SQL 不提交，会静默丢）。

模板骨架：

```python
col = Collection(LIVE)
m = col.models.by_name("生活摘录")
m["tmpls"][0]["qfmt"] = "…"      # 改内容，别动 m["tmpls"][0]["id"] 和 ord
col.models.update_dict(m)
```

加字段：

```python
m = col.models.by_name("生活摘录")
col.models.add_field(m, col.models.new_field("新字段"))
```

批量改数据：

```python
nids = [r[0] for r in col.db.execute("select id from notes where mid = ?", m["id"])]
for nid in nids:
    n = col.get_note(nid)
    if n["某字段"] != 目标值:
        n["某字段"] = 目标值
        col.update_note(n)        # ← 官方 API，自动提交 + 标脏
```

## 3. 覆盖同步副本（改完必做）

不覆盖的话，用户设备同步时拿到的还是旧副本，看不到改动。

```bash
zsh .ssh/push-finance.sh anki-deploy/replace_sync_copy.py /tmp/replace_sync_copy.py
./.ssh/ssh-finance.sh "sudo $PY /tmp/replace_sync_copy.py"
```

它做 5 件事：备份当前副本 → 停 syncserver → cp 三文件 → `chown hermes:hermes` → 起 syncserver。

**为什么必须停服务**：`anki-syncserver` 常驻占锁，直接读写同步副本会报
`database is locked (5)`，连 `sqlite3 ?mode=ro` 都读不了。

## 4. 版本管理

### 存快照

```bash
zsh .ssh/push-finance.sh anki-deploy/backup_B.py /tmp/backup_B.py
./.ssh/ssh-finance.sh "sudo $PY /tmp/backup_B.py"
```

快照内容（`backups/<字母>/`）：

```
collection.anki2  -wal  -shm   工作库三文件
notetypes.json                  三个笔记类型的 fields / tmpls / css 全文
SKILL.md                        Hermes 制卡技能
README-<字母>.txt               这一版是什么 + 怎么回滚
```

命名：按字母递增。**A = v6.1，B = v7**。改之前先存一个字母。

### 回滚

```bash
sudo systemctl stop anki-syncserver
sudo cp $BAK/B/collection.anki2*  /var/lib/anki-autocards/
sudo cp $BAK/B/collection.anki2*  /var/lib/anki-autocards/sync/anki/
sudo chown -R hermes:hermes /var/lib/anki-autocards/sync/anki
sudo systemctl start anki-syncserver
```

## 5. 验证

```bash
zsh .ssh/push-finance.sh anki-deploy/verify_v7.py /tmp/verify_v7.py
./.ssh/ssh-finance.sh "sudo $PY /tmp/verify_v7.py"
```

它会打印：字段列表、模板名、`mode-read` 条件在不在、CSS 关键规则在不在、
各类型的 `自测` 回填对不对、**卡片总数**。

### 每次部署后必须核对的三个数

```
notes  = 3641      ← 3607 + 34 张「使用说明」卡
cards  = 6829
revlog = 2232      ← 这个掉了就说明卡片被重新生成过、复习历史丢了
```

**2026-09-20 牌组迁移后实测：三个数一个没变（revlog 2232 一条不丢）。**
迁移只改卡片的 `did`（牌组归属），不动 `id` / `ord`，所以复习历史天然安全。

### 渲染验证（最直观）

导出服务器**已部署**的模板 + CSS + 真实卡片，在本地用真实浏览器渲染：

```bash
# 服务器
zsh .ssh/push-finance.sh anki-deploy/dump_v7_check.py /tmp/dump_v7_check.py
./.ssh/ssh-finance.sh "sudo $PY /tmp/dump_v7_check.py && sudo chmod 644 /tmp/v7check.json"
./.ssh/ssh-finance.sh "sudo cat /tmp/v7check.json" > restore/v7check.json

# 本地
cd design && python3 render_v7_check.py
NODE_PATH=…/node_modules node shot_cards.js   # 出 PNG
```

预期输出（这就是「两种形式真的分流了」的证据）：

```
观点   front  mode-read=False  body=False    ← 回忆：正面只给提示
观点   back   mode-read=False  body=True
句子   front  mode-read=True   body=True     ← 通读：正面就展开
句子   back   mode-read=True   body=True
```

## 6. Hermes 技能（SKILL.md）

```bash
# 改之前先备份
sudo cp $SKILL $SKILL.bak-$(date +%Y%m%dT%H%M%S)
```

- SKILL.md 是 **Hermes 制卡时读的唯一规范**。改版式/形式映射，必须同步改它。
- frontmatter 的 `description` 决定**什么时候触发**这个技能，别乱改。
- 现存多个 `.bak` / `.v1.bak` 备份文件，清理前先问用户。

## 8. 安全护栏

- **绝不允许 FULL_UPLOAD**。`anki_cli.py` 遇到 `required=4 (FULL_UPLOAD)` 抛
  `SafetyError` 自动中止。这是保护用户设备的最后一道闸。
- 同步状态枚举：`0=NO_CHANGES 1=NORMAL_SYNC 2=FULL_SYNC 3=FULL_DOWNLOAD 4=FULL_UPLOAD`
- 出现 `required=2 (FULL_SYNC)` → 工作库与同步副本差异过大，**不要硬推**，
  先确认方向，必要时用 §3 覆盖副本。
