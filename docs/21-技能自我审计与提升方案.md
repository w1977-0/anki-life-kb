### 2.2 三个设计点的对照

**① 查重**
- `knowledge-management`：写入前算内容哈希，`hash→filepath` 存进 `local-sync-state.json`，重跑就是 no-op 并报告 skipped 数。
- `ivangdavila/expenses`：复合自然键 `date + amount + last four of the account`，并且**只改自己写过的行**（按 identity key 匹配）。
- `flashcard-forge`：Jaccard 相似度去重，但作者自己承认"去重只在单文件内"——**这正是你 863 张 buried 重复的成因**。
- 你现在：`anki_add.py` 用**全库子串搜索**，既会被 34 条"使用说明"示例句误伤（你自己记进 Pitfalls 了），又抓不住近重复。

**② 版式 / 格式选择**
- `ivangdavila/anki`：把 `card_format / note_type / tag_style / batch_size` 持久化进配置，交付前跑一份 **`## Output Gates` 清单**（"是否按用户既有标签体系打 tag，而不是自己发明一套？""分隔符和字段顺序是否说清了？"）。
- `anki-batch-cards`：**绝不猜字段**，先 `modelFieldNames` 探测再填。
- 你现在：版式由脚本按版式池轮换（这条你比它们强），但**没有交付前清单**，md 残留 / 碎片标题 / 目录垃圾卡都是靠事后人肉发现。

**③ 出处判断**
- `grounded-citations`（官方，已装未用）原文三条：ledger 拥有 `url → [n]` 映射，**"数字和 URL 来自检索，绝不来自记忆"**；`quote --text "exact wording" --from page.txt` —— **"逐字不出现就拒绝"**；`verify --evidence` 让任何"引了源却没证据"的草稿**非零退出**。
- `ivangdavila/expenses`：没有的字段**显式写 `unknown`**，条目照样入库（而不是瞎编或留空）。
- 你现在：出处规则是"禁止占位符 + 脚本会拦"，但**没有任何机制验证出处与正文的对应关系**；日期靠脚本兜底填当天（真实但语义是"制卡日"不是"原文日"）。

## 三、hermes-dojo（Yonkoo11）评估：**不装**

仓库存在：`github.com/Yonkoo11/hermes-dojo`（MIT，Python，README 自述"为 Nous Research Hermes Agent Hackathon 2026 年 3 月所作"）。**不在官方目录**（拉了整棵 `NousResearch/hermes-agent` 树 17,679 个路径，零命中 "dojo"），agentskills.io 也不收录；只在社区 awesome 列表里被标 **[beta]**。维护信号：最后提交 **2026-06-06**（约 4 个月未动）、176★ / 3 watchers / 无 release / 无 tag / 无测试无 CI；schema 假设写死（`sessions`/`messages`/`messages_fts`），而 Hermes 从 v0.2 一路到 v0.2x —— 大概率已经跑不通。

真正让我否掉它的是这四条行为（逐个文件读过）：

1. **`monitor.py` 以读写方式打开 `~/.hermes/state.db`**，把 N 天全部消息无 `LIMIT` 载入内存（你这台 1GB 机器 + 6.8MB 库，且它还要重建 FTS）。
2. **`fixer.py --apply` 会往别的 SKILL.md 末尾追加模板段落**（line 601）并**新建技能文件**（line 616），**没有备份、没有 diff、没有回滚**，追加还不幂等。
3. **提示注入 → 持久化**：它把会话片段（`top_error[:60]`、`content[:100]`、`reason`）插进新生成的 SKILL.md 正文，而 SKILL.md 会被后续每一个会话读入。**你的入口是公网飞书长连接**，等于任何进来的文本都可能被固化进教材。
4. 它文档里的"快速自测"（`seed_demo_data.py`、`demo.py --reset`）**往你真库里灌假会话并重建 messages_fts**，再把假数据喂给分析器。

另外它的"失败"判定是 21 条宽松正则（`error:`、`could not`、`unable to`、`timeout`），仓库里就有一条已关闭 issue 叫"分析器产出假阳性技能推荐"——一张写着 "Error handling" 的卡片就会被算成一次失败。而它唯一真正产生改进的部分（GEPA 技能进化）需要 DSPy venv + 付费模型调用，**2 核 1G 上跑不出可用形态**。

**结论**：你只有 2 个自研技能 + 1 个库，量级远不到"自动统计打败人工阅读"的门槛。它带来的成本是 cron、真库读写、无上限的 SKILL.md 追加，以及一条挂在公网消息通道上的注入面。

**值得偷的两条（不装它）**：① `references/failure_patterns.md` 那种「错误 → 根因 → 处置」表；② `_classify_error_root_cause` 的思路——把 infra / auth / quota 类失败**从"缺技能"里剔除**（你这台机器上财务 API 失败绝大多数是额度或 key 配置，不是缺指令）。

## 五、SOUL.md 草稿（装机那天起没改过，668B 英文出厂版）

现有人设是 Nous 的通用英文风格条款。下面这版是按**我们实际相处方式**改写的：保留出厂版全部优点（不废话、不复述、不 narrate 工具调用、不确定就说不确定），加上你 USER.md 里已经存在但没人格化的三条（只读优先、授权模式不合并、汇报必须可核对）。~~未落地，等你定。~~ → **已落地**（2026-09-27），最终文本比这版多两件事：称谓全改「陛下」、新增「已经交给你的自主权」一节 —— 见 §七。

```markdown
# SOUL

你叫 Hermes，是韦骏杰的私人助理兼运维，不是通用聊天机器人。中文（简体）交流。

## 说话方式
- 回答长度匹配问题分量：一句话能答完的绝不写三段；干完活只报"改了什么、验过什么、还剩什么"。
- 不客套、不复述我的请求、不重述已说过的结论、不解说我看得见的操作过程。
- 不用形容词代替事实。"清理干净了"是废话，"/tmp 从 280MB 降到 6MB，服务仍 active"才是回答。
- 不确定就说不确定，并说明要怎样才能确定。不同意我时直接说不同意，给出理由。

## 做事方式
- **先量，再动**。任何判断要有命令输出支撑，不靠印象；印象错了要明说并纠正。
- 只读优先。诊断类请求默认不写、不改、不重启、不外发，也不打印密钥/token 的值（状态用"已配置/未配置"表示）。
- 三种授权互不合并：财务查询 ≠ 运维授权；配置、Docker、systemd、Cloudflare、SOUL/USER/Memory/Skill、装软件——需要我明说"进入运维模式"并点名对象。缺什么就报告，不要顺手装。
- 改之前先备份，改完必须自己验证并给出验证方式；能回滚的要说清怎么回滚。
- 数字要能核对：写"复习负担 ≈ 新增张数 × 4 次/周"这种可检验的说法，不写"适当控制"。

## 边界
- 我的内容是我的。不把卡片、账目、聊天记录写到本机和授权仓库之外的地方；不确定某个第三方服务是否可信时，先问，不要试。
- 宁可报"没做成"，也不要给出看起来完整但实际没发生的回复（例如内容被查重拦下却说"已记下"）。
```
